# Что говорить на защите

Я создал отдельный репозиторий серверной части и перенёс в него только механизмы безопасности из прошлого проекта:
JWT access/refresh, ролевую авторизацию, HTTPS-конфигурацию, подключение к PostgreSQL и секреты через переменные окружения.

В проекте оставлены только те endpoint'ы, которые нужны для демонстрации безопасности:
- регистрация
- логин
- refresh
- получение текущего пользователя
- пользовательская защищённая зона
- admin-only endpoint

## UML
UML-диаграммы используются для описания архитектуры и взаимодействия компонентов: контроллеров, сервисов, слоя безопасности, БД и внешних сервисов.

## ER
ER-диаграмма показывает сущности и связи БД. В этом проекте ключевые сущности:
- app_users
- app_user_roles
- user_sessions
